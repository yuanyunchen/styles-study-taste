How the Styles Study pipeline works

Raw web-design votes become taste rules in three moves: make the data cheap to re-read, let vision models describe every page in a fixed vocabulary of styles and design attributes, and admit a style effect only after it survives model, quality and labeler controls.

1 Problem and data

Each tournament yields five correlated votes on four pages, and the raw data, ≈492 GB, is 2.5 times the machine's disk.

143 models rotate in and out, 45.1% of prompts request a style by name, 1,822 outputs are not web pages and 1,848 desktop renders are missing; the median voter appears once. Round order is unique in only 7,616 of 50,000 tournaments.

2 Data engineering

Convert once, then every later step reads in seconds; screenshots stream through the disk instead of landing on it.

Row counts match the source (50,000 / 200,000 / 250,000 / 36,285). Downloads ran at about 440 MB/s and overlapped processing; labeling uses one desktop full-page image per page.

3 System architecture overview

Three entities: human preference data trains the analysis system and calibrates the evaluation system; the evaluator then tests the analysis system's output, taste.md.

(a) judge with vs without taste.md on 500 pairs (300 Sep + 200 Jun–Aug); rules were derived from data including September; (b) 89 prompt × model pairs generated with and without taste.md, each judged blind by 3 models, clustered by prompt. Dashed boxes are designed but not built.

4 Analysis system

Five layers; each layer can call any layer below it, so a researcher can query facts, refit the model or commission a fresh vision probe.

Bottom layers are breadth (every page, cheap), top layers depth (few questions, targeted). Findings below grade B never reach the training file.

5 Evaluation system

A cheap model explores widely and hands over a compressed evidence pack; a strong model judges with the original prompt, and independent checks cross-validate before a preference is issued.

Compress the process, never the counter-evidence.

Agreement signals confidence; it does not prove correctness.

9 Scaling loop

A monthly refresh costs about one labeling pass and one engine run; the hand decisions made in this study are already encoded as gates.

Labelers: DeepSeek V4.1 Flash (1017 build) as primary; GPT-6 Luna and Claude Haiku 5.5 for probes and cross-checks. Labeling cost ≈$0.000155 per page for style labels and ≈$0.00031 for Design DNA; the main scaling risk is labeler drift (repeat agreement 0.673 under default routing).
